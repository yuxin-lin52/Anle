# 09 错误处理与错误码

状态：已实现（双轨错误处理与错误值已落地；错误码体系已实施）。

## 规则

失败分两类，归类在设计期由类型定死：

| 类别 | 机制 | 例 |
|---|---|---|
| **bug**（不应存在的状态） | **护栏终止**：除零、下标越界、悬空把手、安全层溢出、失控递归 → 报行号退出 1 | `10 / 0` |
| **预期失败**（正常流程的一部分） | **错误值**：和类型 + match（编译期穷尽检查）——错误即普通值 | 文件不存在、输入不合法 |

```anle
add type "算结果" = 得(int) | 败(str)
add fn "安全除" (a int, b int) 算结果 = (b == 0) ? 败("除零") : 得(a / b)
match call fn "安全除"(10, 2):
case 得("v"):
;1 print(call val "v")
;
case 败("因"):
;1 print(call val "因")
;
;
```

- 传播不加糖：调用、解包、继续。啰嗦的部分可写成 fn 复用。
- **错误码**：编译期诊断 `E0–E4` 按阶段（词法/语法/检查/中间表示/后端）、`E5–E9` 按归属（工程配置/环境/编译器内部/预留/兜底）。唯一判据：**改自己的源码能消掉归 E0–E4，否则 E5–E9**。运行期护栏用 **R 系**（R01 悬空把手、R02 除零、R03 溢出、R04 越界、R05 键不存在、R06 内存不够）。
- 诊断带四段：位置（文件行列）、动作、错误描述、**改法**。严重度四级对齐 LSP。
- **护栏随编译模式**：debug（默认）下容器访问检查全部生效——下标越界（R04）、键不存在（R05）。`--mode release` 下这些检查从产物中移除：不是跳过，是不存在，无任何运行时开销。release 下越界属未定义行为；两种模式对合法程序的输出逐字一致。

## 理由

- 双轨是必然形状：让 bug 继续跑没有意义，预期失败是正常流程——区别只在 bug 轨是否确定。Anle 把它确定化：报行号退出，不是未定义行为。
- 错误即普通值：零隐藏控制流、零运行时开销，但裸返回码的错误可无声忽略、无类型支撑、解包样板无穷尽。和类型加编译期穷尽 match 正好补上这三条。
- 不加传播糖：糖取决于语言的表达结构。fn 体与 match 放开后，啰嗦可用辅助 fn 缓解。真实项目证明痛感超阈值时单独评估。
- 异常与 try/catch 永不：隐藏控制流加运行时展开机制，与 AOT、无运行时、二值化三原则冲突。
- 错误码分段判据：「改自己的源码能否消掉」一刀切开两轴，防止阶段与归属交叉。

## 显式不提供

- 传播糖（`?` 式）——真实项目证明痛感超阈值时再评估
- 错误栈 / 回溯——调试靠报错行号
- 异常机制、try/catch——永不
- 旧内置迁移为错误值——破坏面大收益零；新代码用错误值风格

# 14 内联汇编

状态：已实现。

## 规则

两种形态，均属 unsafe（内联汇编是 unsafe 的第四件事，与 MMIO、C 互操作、`kill` 并列）：

- **块级 asm**：`#: 名 b asm` 开块，块体就是原始汇编文本。编译为 naked 函数——没有编译器生成的序言与收尾。用于中断/异常入口、上下文切换桥、屏障与原子指令序列。无参数无返回值；ABI 约定由调用方自担。
- **内联 asm**：fn 内 `asm("模板" : 输出 : 输入 : 破坏)`，GCC 三段式——与 clang 的 `__asm__("in al, dx" : "=a"(结果) : "d"(端口) : "memory")` 一一对应。输出写 `寄存器 -> 名`；读写用 `<->`；输入写 `寄存器 <- 表达式`；破坏段手列 `memory` 或寄存器名。命名操作数产成 `%[名]`。体末是带输出约束的内联 asm 的 fn 是表达式，可赋给 val。

规则：隔离区（asm 括号内）用 asm 自己的微语法解析，不吃 Anle 词法——`in`/`out` 等约束词不与 Anle 的 `in` 关键字冲突。隔离区只准 ASCII：模板、绑定名、破坏段不出中文。模板不跨架构（`al`/`dx` 是 x86 专属）；按架构分写用 `only(x86_64)` / `only(arm64)` 门控。

## 理由

- 裸机需要它：内核入口点、上下文切换、特权寄存器（`CR0`/`CR3`/`LGDT`）、真原子指令只能以内联汇编书写（C 里也是）。
- 无约束的内联汇编被否：它对别名分析、回收点、`kill` 追踪完全不可见，会破坏内存模型。带约束声明（声明输入/输出/破坏/内存副作用，编译器据此保守）不破坏——代价只是汇编点局部抚平优化与回收。
- 约束必须显式：漏写副作用即报错——纪律是响亮优于安静。
- GCC 三段式而非关键词式约束：破坏段手列，与汇编程序员既有习惯一致。

## 显式不提供

- 运行期拼接模板的 asm——约束必须编译期可知；否则等价无约束 asm，永不
- 跨架构可移植 asm——指令集本质不同；用 `only(...)` 门控分架构写
- 隐式约束推断——推断是猜，猜错危险，永不
- 独立汇编文件（Go `.s` 式）——需要定义 Anle 汇编 ABI；内联加 C 互操作已覆盖
- asm 进编译期求值——编译期执行 = 执行目标机指令，永不

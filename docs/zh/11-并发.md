# 11 并发：静态水印时序

状态：语义预占（设计已锁定，防止其他设计与它撞墙；本体实施排期另定）。

## 规则

1. 对共享数据的操作显式标注时序（E1、E2、E3…）。En 执行前等待 E(n-1) 的水印，完成后盖自己的号。并行部分照常并行，只有共享数据的触碰点按序等。
2. 只许等比自己小的号——死锁在结构上不可能，编译器可查环。
3. 顺序完全由源码定死，每次运行可复现（确定性并发）。运行期可以有机制（计数、睡眠/唤醒等 OS 原语），但它们不做任何顺序决定。
4. 数据沿链移交：发送后原件作废。「通过副本写回」在结构上写不出来，因此合并冲突不存在。
5. 私有计算不标号：各线程在自己地皮上的生产与处理天然并行。把私有步骤也标进号链 = 整条流水线焊死成串行。
6. 跨线程循环是会合驱动：循环是否继续由对端经水印链发回的信号决定（信号存 val、循环头读取）。带条件终止、总量未知的流式场景可做且内存恒定。停止协议是哨兵移交。
7. 发号机是用户层代码——语言只提供静态水印。

## 理由

- 确定性内存要求执行流可算：共享可变状态必须限制到显式通道，否则回收点不可算。安全确定性与自由共享内存并行二者取一——本轮取前者，**共享内存并行这片上限有意砍掉**（经质询确认）。
- 运行期取号被否：顺序由到达时机决定违背「顺序源码定死」。
- 所有权 + 运行期阻塞被否：确定性与无死锁两个优点同时退回。
- unsafe 共享内存通道不内建（用户否决）：竞争与合并问题随内建回归。
- 诚实代价（写死）：圈数配错是死等，编译期查不出（流式编程固有负担）；会合循环是锁步交替，没有计算重叠——多核收益靠批量化或手动双缓冲，两者都是静态零机制。

## 显式不提供（原生不提供 ≠ 拒绝；unsafe 与 FFI 是通用逃生舱，自建即脱离确定性担保）

| 原生不提供 | 自建途径 |
|---|---|
| 运行期发号 / 取号 | 用户层发号机 |
| 锁 / 互斥量 | unsafe 自旋锁，或 FFI 调 pthread |
| unsafe 共享内存通道 | 两线程读写同一地址 |
| 原子操作原语 | FFI 调 C 原子库 |
| 通道关闭原语 | 哨兵移交协议 |

# 06 函数

状态：已实现。

## 两种体

默认是公式体：

- 公式体：`add fn "名"(参数) 返回类型 = 表达式`——单表达式，允许 call 嵌套，禁止语句。
- 语句体：`add fn "名"(参数) 返回类型:` 开体，独占一行 `;` 收束。体内允许局部 `add val`、重绑定、`if`/`while`/`for`/`match`、调其它 fn、递归。返回值是 `give 表达式`，必须是最后一条语句（单出口；分支内 give 报错）。
- 参数按 `call val "名"` 读取——语句体内没有裸名豁免。参数类型与返回类型必写。

## 调用

`call fn "名"(实参)`——同块；跨块跨模块加前缀（见 [02-基本概念](02-%E5%9F%BA%E6%9C%AC%E6%A6%82%E5%BF%B5.md)）。外部 C 函数用 `add outs fn "名"(参数) 返回` 声明，仅 unsafe 块内调用。

## 一等函数

函数类型存在：`f fn(int) int`。函数可以当参数传、存 val、装容器、当返回值、按同一性比较——纯函数指针，无捕获。

## 理由

- 公式体（函数即它的值，无 `return`）：单表达式体是验证过的初学者友好形态，对工具也无歧义。
- 语句体存在是因为库函数写不出来：`split` 需要「边循环边构造结果」，公式体表达不了（没有循环、没有语句），块又不能返回。
- 叫 `give`：语义是「把值交给调用者」，与 `call` / `take` / `kill` 同族。`return` 是各家从 C 继承的词；本语言一贯避开主流关键字。
- 单出口先行：多出口需要控制流合并分析。单出口已覆盖「边循环边构造」；中途 give 等真实需求出现再评估。
- 无闭包：捕获会延长外部值的寿命，撞确定性回收。函数记录（struct 装 fn 装数据）以显式寿命覆盖用例。
- 块不加返回值：块 = 过程、fn = 公式是设计级决定。要从块里拿值，就在块里写个 fn 收尾再显式去取。

## 显式不提供

- 块返回值（角色边界）
- 中途 `give` / 早返回（控制流合并分析；后续批次）
- 闭包捕获与匿名 fn（见上）
- 栈溢出护栏之外的深递归保护（用户责任）

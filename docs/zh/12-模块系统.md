# 11 模块系统

状态：已实现。

## 规则

- 编译单位是目录：`anlec build <目录>`。入口固定在目录根的 `main.an`——零配置。边界是命令行给的目录；编译器绝不向上搜索工程根。
- 一文件一模块。模块名 = 目录路径 + 去扩展名的文件名，目录分隔符映射为 `.`（`前端/分词.an` → 模块 `前端.分词`）。路径即命名空间。移动文件就是改名（知情接受的代价）。
- 依赖闭包靠递归扫描 `##:模块` 前缀收集。每个模块只编译一次；允许循环引用（合源编译下无害）；未被引用到的 `.an` 文件不参与编译。
- 合源编译：闭包合并为一份 IR、一个可执行文件，用户零感知。
- 可见性：跨模块调用只能命中 `pub` 块（默认私有）。`hide` 从公开面剔除个别项。作用边界仅跨模块——同模块内其他块仍可调用。
- 类型名全程序唯一，含和类型变体名，跨模块亦然。依据：删 use 后没有 import 作用域、构造又是裸名 ⇒ 裸名必须唯一才能指称。
- 诊断归属实际源文件——库文件里的错误报那个文件的名字与行号，不指向 `main.an`。
- 块名同模块内唯一；跨模块同名允许——这正是 `##:模块` 消歧的意义。

## 理由

- 范围先划清：v0.x 只解决把一个程序拆到同机多文件。包管理、增量编译、版本锁定明确划出——生态与缓存是后续台阶。
- 模块 = 文件、路径即命名空间：规模大了仍有秩序。代价（搬家 = 改名）换「大工程的秩序 > 最小实现的方便」。
- 编译边界显式：自动向上搜工程根的最坏情况是搜到盘根。命令行给目录——一条规则零歧义。
- 分发是普通 zip：Windows 隐藏扩展名下改后缀（.anp）反人类；真正的应用格式（带 manifest）随 v1 积木层另立，不是改后缀的 zip。
- 循环引用允许：合源编译下天然无害。
- 尾名回退：`##:工具` 唯一命中 `库/工具.an`；撞多个模块报响亮的歧义错误并列候选。

## 标准库

两层：

- **底座**：OS 最后一厘米的薄内置层，加一份稳定的 runtime 符号契约。契约与后端无关——C 后端链 `anle_rt.c`，LLVM 后端链同一套符号，未来的后端照同一规矩。当前底座（约 40 个内置）冻结。
- **上层**：纯 Anle 源码，完全与后端无关，经模块系统引入。API 形态：模块前缀函数（`字符串.分割(串, 分隔)`）。

第一批（全部零底座依赖、纯 Anle）：字符串五件（分割、修剪、查找替换、大小写转换、搜索）；容器算法三件（映射、过滤、折叠——泛型自由函数，变换与判定逻辑是 fn 参数）；泛型包装两个（`结果(T, E)`、`可选(T)`）。

## 显式不提供

- 包管理 / 依赖下载 / 版本锁定——v1 生态议题（包坐标 `lib.作者.仓库`、清单 `lib.anle`、接口清单 `api.anle`、三级前缀 `###:` 已设计）
- 增量编译——编译毫秒到秒级；模块级增量是真增量的前置
- 环境注入 / 注册表 / 安装器服务——见 SDK 打包设计

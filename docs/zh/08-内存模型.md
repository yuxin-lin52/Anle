# 05 内存模型：地皮树

状态：已实现。

## 规则

- 内存按块实例分配。块的地皮回收时，其中一切随之回收；回收是每段 O(1)，不是逐对象。
- 地皮构成树：段挂在调用者段之下。块出口不回收——地皮活到调用链尽头（父死子亡）。链根出口递归回收整树。
- 回收点在编译期由块引用图定死。运行时没有 GC 线程、没有全局停顿、没有引用计数。
- 段池（64KB 统一块 + 大块特例）回收死段；无主段还池，下次同尺寸分配优先命中。
- 圈级回收：循环体内调用产生的子段在每圈末尾批量还池。由编译器隐式执行，保守分析（仅当无数据跨圈逃逸时启用）。
- `kill`（仅 unsafe 内）：语句 `kill #:块` 回收目标块的全部活跃段及其子树；关块行后缀 `#: 块 d kill` 在出口清理本块自身。约束：仅顺序语句位置；目标非当前块且被本链调用过。编译器追踪每一条把手与引用槽传播路径——kill 点存在活引用即编译错误，并列出全部违规。

## 理由

- 地皮逻辑上是树（兄弟相互独立）；此前的栈实现是 LIFO——兄弟独立回收与提前释放都做不到。这就是要修的缺陷本身。
- 编译期定回收点是前提而非选项：无 GC 线程、无停顿、无计数、引用环不泄漏四条性质全部由它推出。
- 前例：区域推断系统的区域仍是栈式嵌套（兄弟独立失败）；显式 region 方案把句柄引入类型系统、堆区留给运行期回收器；所有权按值粒度、检查负担在人；引用计数有运行期开销且环泄漏。都不合。
- 块的划分只影响内存占用，不影响正确性——回收粒度是性能旋钮，不是正确性要求。因此不设块粒度规则，编译器也不提醒。
- `kill` 用追踪而非静默：失败即编译错误并列出全部违规引用。响亮优于安静。

## 显式不提供

- 段压缩 / 搬移（会使把手失效；碎片由 64KB 段池吸收）
- 编译器发起的提前回收（编译器不替开发者做性能决策）
- 常驻块 / `promote`——另立议题
- 跨进程地皮——段树限单进程单链

# 02 基本概念

状态：已实现。

## 块

所有代码写在块里。块用 `#: 名 b`（born）开、`#: 名 d`（death）关。块是平的——不嵌套。`in #:父` 只做展示分组，无语义作用。

运行时块成链：没有被任何块引用的块是链根，所有链按源码顺序自上而下跑；被引用的块在调用处执行。互相调用又无链根的块，编译期报错。

## 创建与改绑定

名字用 `add` 创建，只出现一次：`add val "名" = 值`、`add fn "名" (参) 返 = 体`、`add type "名" = 定义`。改绑定不用 `add`——写 `val "名" = 新值`。对没建过的名字写 `val "名" = 值` 是编译错误；不存在「首次赋值自动建变量」。

`add` 不带 `=` 是纯声明（登记名字与签名）；之后一行补体——补体形态与带 `=` 完全一样，只少 `add`。

## 全面显式

读值写 `call val "名"`，调函数写 `call fn "名"(…)`。裸名被拒——`fn` 与 `val` 可重名，裸标识符说不清指哪一个。

## 动词位

`call`（引用槽——要最新值）、`take`（深拷——要当时的值）、`kill`（显式提前回收）。三者都显式写明目标来源；裸的跨块访问一律拒绝。

## 理由

- 块平铺：块既是过程的单位也是内存的单位。嵌套会把两者依赖的边界搅糊。
- `add` 一次：重复 `add` 会把「改值」误变成「重建」。首次赋值自动建变量把拼写错误藏成新变量。两头堵死，拼错名字必然响亮报错。
- 全面显式：`fn` 与 `val` 可重名，读取必须带类别标签。代价是每处多敲几个字；收益是任何读取都不依赖上下文。

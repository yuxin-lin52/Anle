# 10 编译期求值

状态：已实现。容器常量尚未实现。

## 规则

- **常量 = 第五类有名实体**：`add fix "缓冲" int = 4096`。不可改赋（对 fix 写 `val "名" = …` 报错）——这是语义本体，不是待解除的限制。
- **编译期执行自动触发**：实参全为编译期已知的调用在编译期解释执行，产物直接当值。没有 comptime 标注——编译期是值的性质，不是另一种代码。
- **编译期分支零新语法**：条件为编译期已知的 `if` 被裁剪，未中侧不产码。
- **失败必须响亮**：常量表达式无法求值时报编译错误——绝不静默退回运行期。
- 红线：编译期**禁 I/O、禁依赖运行期值**。

```anle
add fix "缓冲" int = 4096
add fn "双倍" (n int) int = n * 2
add fix "甲" int = call fn "双倍"(21)
if 2 > 3:
;1 print("这段永远不产码")
;
```

## 理由

- 买的是能力，性能搭车。真实收益三处：查表预计算（启动期计算归零，表进只读内存）、分支裁剪（未中侧零产码）、静态布局（尺寸编译期已知，进数据段）。简单常量折叠 -O2 本来就会做——不是卖点。
- 自动触发而非标注：编译期是值的性质。要求每个函数标 comptime 是把这件事变重。
- 常量不可改与 val 的可改构成二值：fix 在编译期定死，改赋即错，没有回退。
- 宏的替代路线：宏的四个用途——样板消除（泛型）、编译期查表（本机制）、领域方言（与哲学冲突，不做）、自动派生（反射，远期）。文本宏与词法流地基冲突。**元编程需求由编译期求值加泛型承担；不立宏。**

## 显式不提供

- 显式 comptime 标注语法——永不
- 编译期 I/O——红线，永不
- 容器常量——需要静态数据段支持；当前明确报错，不静默退化
- 语句层解释（局部变量、循环进编译期）——随语言能力扩展
- 编译期反射——远期议题（依赖类型信息暴露设计）

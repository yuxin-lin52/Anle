# 13 可移植性与目标

状态：已设计，尚未实现。

## 规则

* 目标是三个正交维度加一个栈预算：`system`（windows / linux  / none 裸机）× `arch`（x86\_64 / arm64）× `backend`（c / llvm / asm 最后），加 `stack`（如 `8M`）。
* **能力分面。** 内置名按面归属，共八面——`pure`（纯计算，零依赖，裸机也有）、`console`、`file`、`process`、`time`、`random`、`hw`、`ffi`。每个目标声明实现哪些面。程序用了缺失的面 = 编译期拒绝并列缺失清单。移植 = 按面付款：纯计算面零工作，最小可跑（exit + 输出）只要两个函数。
* 内置预设目标（如 `windows/x86\_64/c`，全八面，已验证）加自定义目标描述文件——核心字段是 `faces`。加目标 = 加数据，不改编译器。
* 块级门控 `only(目标)`：`#: 问候\_win b only(windows)`——整块进出；未命中的块不检查、不产码。主代码零分支。语义差异由底座吸收（平台分支写一次，写在编译器内）。
* 栈：预算可在构建配置里显式设定（构建期写入产物）；护栏页加 runtime 胶水永远兜底——栈耗尽是干净的「栈耗尽」报错并退出 1，不是裸段错误。
* 构建配置：极简键值格式，两个文件（`lib.anle` 包元信息、`build.anle` 构建配置），UTF-8 无 BOM、LF。

## 理由

* 移植的本质：编译器永远不需要知道新系统怎么调功能——它只产出符号调用，符号的真身由目标提供。
* 自定义目标是数据不是代码：加目标 = 写文件。
* 能力分面：源码在语句级零分支——平台差异全部在底座内吸收（中文文件路径、平台睡眠 API——全在编译器内部）。块级门控处理吸收不了的差异，用声明式形态：整块进出，被排除的块如同不存在。
* 不做探测降级（「缺 A 面换 B 写法」）：违背二值化。正确姿势 = 源码写在公共能力子集内。
* 语句级条件编译（`#if` 类）被拒的判据与拒绝纯缩进相同：它让语义依赖符号的位置。块级门控加编译期分支裁剪覆盖所有场景。

## 显式不提供

* 语句级条件编译（`#if` 类）——块门控加编译期分支覆盖所有场景，永不
* 探测降级——违背二值化，永不
* 运行期栈配置——构建期定型，永不
* 变量名级调试映射——深调试走 print 约定
* 线程栈策略——并发本体实施期定

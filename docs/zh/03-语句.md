# 03 语句

状态：已实现。

## 控制流

`if` / `else` / `for` / `while`，体以独占一行的 `;` 收束——缩进纯属装饰、不可能改变语义；`;` 不配对是响亮的解析错误。`else:` 必须紧跟其 `if` 体的收束 `;`。

- 条件必须是真假值——`if 5:` 被拒。
- `for i in 1~5:` 走含两端的范围；`for x in 集合:` 遍历容器与字符串。
- `while 条件:` 自由循环；`while 条件 max 100:` 硬性圈数上限（卡死保险，不是禁令）。
- 循环变量是可赋值局部；`max` 要求整数字面量。

## match

```anle
match call fn "安全除"(10, 2):
case 得("v"):
;1 print(call val "v")
;
case 败("因"):
;1 print(call val "因")
;
;
```

- `case 变体(绑定)` 解构负载；`case _:` 兜底。
- match 对象收「类型可推断的表达式」。
- 编译期穷尽检查——新增变体会暴露所有未更新的 match。
- 语句形态（如上）与表达式形态（fn 体内）都存在。

## 赋值与改绑定

- 改绑定：`val "名" = 新值`。
- 增量：`val "次" = val "次" (+1)`——把括号内的表达式以当前值为左操作数应用；必须有当前值。
- 下标与字段写：`列表[1] = 值`、`head.next.值 = 90`——写位置保持裸。

## kill

unsafe 块内：`kill #:块` 回收目标块的活跃段；`#: 块 d kill` 出口清理本块自身。仅顺序语句位置；目标非当前块且被本链调用过。编译器追踪每一条把手与引用槽传播路径——kill 点存在活引用即编译错误，并列出全部违规。见 [08](08-内存模型.md)。

## 理由

- `;` 收束 + 缩进纯装饰：纯缩进失败模式是静默——缩进错位改变语义。缺 `;` 是响亮的解析错误。
- 真值条件被拒：把数字当真假是隐式转换，隐式转换是 bug 藏身处。
- `max`：无限循环本身合法，上限是卡死保险。
- 穷尽 match：变体是封闭集合；新增变体当场暴露所有未处理的 match——编译期保证，不是约定。
- `kill` 用追踪而非静默：失败即编译错误并列出全部违规引用。响亮优于安静。
